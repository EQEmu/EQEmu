## 4. Traps hit this session — each cost real time

### ⚠️⚠️ Listbox colours are `0xAARRGGBB`; `0x00…` is INVISIBLE
Alpha 0 means fully transparent. The Autoskill list showed an empty red selection bar and **no
skills**, which read as "no data" rather than "no alpha". `core_advloot` was right by luck, which made
the others look like a data bug. Also: **`AddString` colours column 0 only** — later cells need an
explicit `SetItemColor` or they draw black.

### ⚠️⚠️ NEVER edit Lua (or anything) with `perl -0pi -e`
Three separate corruptions, all mine:
- `"^sjinfo%s+(%d+)%s*$"` → `"^sjinfoH PA u+(1990222272+) +z * )` — perl interpolated `$"` and `$+`.
  `global_player.lua` requires `spell_choice`, so **the entire picker died** and the only symptom was
  one `error loading module` line in the player's chat.
- `$_` in a replacement inlined the whole slurped file into `gen_stock_pool.pl`.
- `%%d %%b` reached the C source verbatim, so `strftime` printed `%d %b` on screen.

**Use the Edit tool, or single-quoted `sed` with line numbers.** Then run luacheck.

### ✅ There is now a Lua syntax checker: `.devcontainer/custom/tools/luacheck`
The container has no `lua`/`luac`, so a broken quest module could only be found by restarting zones
and reading a player's chat. `luacheck.c` links system Lua 5.1 and calls `luaL_loadfile` (parses,
never runs — safe for `eq.*` scripts). All 4,261 quest files pass.

```bash
find .devcontainer/repo/quests -name '*.lua' -print0 | xargs -0 .devcontainer/custom/tools/luacheck
```

### ⚠️⚠️ Do not put buttons in the stock SC / EQ bar — it was tried and it CRASHED
An `EQM_AoTButton` in `EQUI_EQMainWnd.xml`, with its click caught by copying `EQMainWnd`'s vtable and
overwriting entry 34. **Crashed on the first click.** Reverted; the file is stock and unshipped.
A second attempt — removing the bar's `<Pieces>` to hide it — **broke world entry**, because client
code dereferences those children. Both are documented in `core_aotmenu.h`. The launcher is our own
window for this reason.

### ⚠️⚠️ `ninja` exiting ≠ the link being done — and killing `ld` DESTROYS the binary
`ld` runs for minutes after the compile lines stop, and the binary's mtime updates when the linker
*creates* it, not when it finishes. Restarting zones mid-link makes eqlaunch spawn a half-written
binary; they die instantly and leave zombies. **Check `pgrep -x ld`, not the timestamp.** (Cost two
false "the server is broken" diagnoses.)

⚠️⚠️ **The danger is not only zone restarts — it is ANYTHING that kills `ld`.** The linker **deletes
`bin/zone` before writing it**, so an interrupted link leaves *no binary at all*, not a stale one.
I did check `pgrep -x ld` and still took the server down, because I killed the linker myself:

- **Never run two `ninja zone` in the same build dir.** The second re-links what the first already
  produced, and they race over the same output file.
- **Never wrap the build in `timeout`.** A `timeout 300 ninja zone` fired mid-link, `ld` died with
  SIGTERM, and `bin/zone` was simply gone. The wrapper existed only to make the *second* ninja safe
  to wait on — the redundant build is what made a wrapper look necessary.

One `ninja zone`, unwrapped, wait for it to finish. Running zones keep serving off the already-loaded
image, so a missing binary only breaks *new* zone boots — which reads as "some zones work" and is
easy to misdiagnose.

### ⚠️ A `<Page>` only renders inside a `<TabBox>`
Removing a TabBox means dissolving its Pages too. Pointing a `<Screen>` at a `<Page>` gives a
correctly framed, correctly titled, completely **empty** window with no error anywhere.

### ⚠️ Brace-balance checks are not verification
Several times I reported "braces balanced" as if it meant the code was sound. Two real compile errors
got through anyway (`Database&` vs `SharedDatabase*`; `buyer_name` on the wrong struct level). Only
the build is a check.

## 5. Stonestride — an AA that never did anything

Worth reading before adding any AA that uses a SPA.

`Stonestride` carried **SPA 162 `MitigateMeleeDamage`** with `base 100, limit N` — the documented way
to get a flat per-hit reduction. It is **inert on an AA**, twice over:

1. `Mob::ApplyAABonuses` has **no case** for SPA 162, so `aabonuses.MitigateMeleeRune` is never filled.
2. The consumer (`attack.cpp:3880`) reads `spellbonuses` only, and pays out of `buffs[slot].melee_rune`
   — a **buff slot**, which an AA does not have.

Contrast **Weathered** (SPA 161): `ApplyAABonuses` *does* handle it and the consumer sums `aabonuses`.
The two look like siblings and behave completely differently — do not assume.

Now a **marker AA** read by `Mob::AoTv4Stonestride`, called from `MeleeMitigation` beside the melee
tree's `AoTv4BacksToTheWall`. Values unchanged (2/4/7/10/14). Floors at 1: reaching zero is
deflection's job, which prints its own message and feeds Aegis Reflex.

⚠️ It is **live for the first time**, so 14/hit at rank 5 has never been tested against real damage.

## 6. Open questions / unfinished

### Missing rows in the Advanced Loot window — instrumented, not solved
Reported as poisons/tradeskill/trash not appearing. I had two theories (corpse-slot bitmask, then
`MakeLootRequestPackets` re-stamping lootslots) and **checked both — neither holds** for a normal
corpse. Rather than keep guessing, `SendAdvLootData` now counts all four skip paths and logs one line
per corpse:

```
AdvLoot [Ashrem] corpse [1234] showed [6] hid [3]:
  no_corpse_slot [0] never_rule [0] not_in_shared_memory [3] row_cap [0]
```

**`not_in_shared_memory` is the prime suspect** — item rows added to the DB without `./shared_memory`
rebuilt resolve to nothing and vanish with no other symptom, which fits poisons/tradeskill exactly.
Ask the player to enable `#logs` (Loot) and kill something.

*(A later message clarified the item DESCRIPTION was blank, not the row missing — that is fixed, see
§7. Whether rows are still genuinely missing is unconfirmed.)*

### `ReclaimOfflineShop` is a landmine
Never called from anywhere, and it ends in a blanket `DeleteWhere` on the character's trader rows.
That predates the escrow rework: items now live **only** as trader rows, so wiring it up as-is would
destroy them. `RefreshShopSession()` was added instead (UPDATE, not DELETE). Rewrite before use.

### Amplification does nothing to Cassindra's Chorus of Clarity — by arithmetic, not a bug
`GetInstrumentMod` starts at 10 and Amplification's base is 2 → 12. `CalcSpellEffectValue` applies it
as **integer** math: `1 * 12 / 10 = 1`. The song's base is **1**, so it needs effectmod ≥ 20 to move
at all, then jumps to 2. Both gates I suspected are fine (`IsBardSong` passes; the song has
`buffduration = 0` so mana effects *are* modifiable). Fixing it means raising the song's base, raising
Amplification's base, or rounding instead of truncating — **the player was asked and has not chosen.**

### Still on the backlog from last session
Portal and Search are still GDI overlays; the Shielded buffs (43380-43382) are still placeholder
marker buffs; `era_system.check_unlock` is still orphaned (nothing advances `aotv4_era`).
