# Kept Spells & Parchment Ranks — design draft

*Status: **BUILT AND LIVE** as of 2026-07-31. This file is the DESIGN REASONING and is kept for the
alternatives it rejects and the traps it identifies; it is **not** a description of the shipped code.*

> ⚠️ **Read `CLAUDE.md` §29 for what actually shipped** — the implementation diverged from this draft
> in one structural way that matters: rank became a permanent property of the **character**, not of a
> kept spell, so *keeping is not how you protect a rank*. Several "open questions" at the bottom were
> answered by that decision (notably #4 — rank persists against the spell id regardless of keeping).
> ⚠️ The suggested numbers below are NOT the shipped ones. Ink is a flat +10 per rank, not doubling;
> the live costs are in `aotv4_spell_ranks_sys.M.COST`, which is the only place to tune them.

Four connected systems:

1. **Keep 2 spells through death**, paid for by forfeiting the level-up picks that produced them.
2. **Parchment Fragments** — awarded on death, one per spell destroyed.
3. **A global drop** — low chance off any mob, the scarce half of the recipe.
4. **Spell ranks 1-5** — +10% output and −5% mana per rank, on a kept spell.

## The id ceiling — MEASURED, not assumed (2026-07-31)

Ranks want real `spells_new` rows, like the native `Rk. II` / `Rk. III` line. Whether that is possible
turns entirely on how many spell ids are left, so it was tested rather than estimated.

### ⚠️⚠️ 45000 IS A CLIENT-SIDE CEILING AND IT IS REAL

Two ceilings had been conflated, and only one of them was ever fixed:

* **Server — already raised.** `RoF2::spells::SPELL_ID_MAX` (`common/patches/rof2_limits.h:346`) was
  lifted 45000 → **50240** by an earlier AoTv4 change, because the spellbook and gem packet builders
  (`common/patches/rof.cpp:2114`) silently DROP anything above it.
* **Client — immovable.** `eqgame.exe` loads `spells_us.txt` into an array indexed by spell id and
  cannot see past roughly 45000.

**The experiment.** Two byte-identical clones of `54 Frost Bolt`, differing only in id: a control at
**44000** and a probe at **46000**, both scribable by every class at level 1, with the client file
re-exported and installed.

| | result |
|---|---|
| `#scribespell 44000` | *"You have finished scribing Control Test Bolt."* — appears in the book, usable |
| `#scribespell 46000` | server reports success; **book slot draws EMPTY**, name resolves as *"Unknown Spell"* |

`character_spells` afterwards held **slot 0 = 46000** and slot 1 = 44000. So the server accepted it,
stored it and transmitted it; the client simply could not render it.

⚠️⚠️ **EVERY SERVER-SIDE SIGNAL REPORTS SUCCESS.** No error, no log line, nothing in `UIErrorLog.txt`.
An out-of-range spell silently occupies a book slot the player can neither see nor clear. This is
why raising `SPELL_ID_MAX` was necessary but never sufficient, and why the original custom set was
renumbered 50xxx → 43xxx.

⚠️ **Do not diagnose this with a single sample above the line.** The first pass tested only 46000 and
got *"finished scribing Unknown Spell"* — which a missing `spells_us.txt` produces identically. The
control at 44000 is what made the result mean anything.

📌 Patching the client array is **not** the answer. We own a dll that patches memory, but this would
mean relocating an array we did not allocate, on a build whose structs already do not match the
headers (§13), failing only at runtime. §21 records the same shape of attempt (overwriting a vtable
entry on a window the dll did not construct) crashing on first click, with a standing note not to
retry it.

### What that leaves — and it is enough

| | rows needed | fits in the 3,951 free ids? |
|---|---:|---|
| ranks 2-5 for the **whole pool** (2,585) | 10,340 | **no** |
| ranks 2-5 for the **reachable pool** (811 at cap 35) | **3,244** | **yes**, with 707 to spare |

At a level 35 cap only **811** spells can ever be offered, so only those can ever be kept, so only
those need ranks. Real rank rows are therefore **viable** — and strictly better than a runtime
multiplier, because a real row shows its real damage and real mana cost in the native spellbook, and
the mana discount becomes genuine rather than possibly-cosmetic (the client checks against the
rank's own cost). Upgrading is unscribe-old / scribe-new, exactly as native `Rk.` lines work.

⚠️ **It spends 82% of all remaining spell id space, permanently**, leaving ~700 for every future
custom line — and 43300-43575 already went on seven lines this year. There is no way to raise the
ceiling, so this is a one-way door.
⚠️ The free ids are **fragmented** (3,110 in one block, the rest in gaps of 2-362), so ranks cannot be
a tidy contiguous band; a generator must assign from a free list.
⚠️ `spells_new` is **shared memory**, so rank rows cannot be created on demand -- every one must be
pre-generated, with world down → `./shared_memory` → restart and a `spells_us.txt` re-export.

📌 **Worth narrowing before generating anything:** if ranks apply only to damage and healing spells
rather than all 811, the id spend drops sharply. That is a design question, not a technical one.

### The fallback, if id space is judged too precious

A per-character multiplier at cast time, using hooks that already exist:

```
stored:   spellrank_<charid> = "<spell_id>:<rank>,..."
applied:  GetActSpellDamage / GetActSpellHealing   x (1 + 0.10 * rank)
          GetActSpellCost                          x (1 - 0.05 * rank)
```

Costs nothing in ids, but the client would display base values, and the mana discount would likely
be partly cosmetic (the client decides whether you may *begin* a cast from its own copy of the cost;
the server only controls what is deducted). ⚠️ Buffs have no hook either way — a stat buff's
magnitude is read straight from the spell row in `SpellEffect` — so v1 should cover **damage and
healing only** under either approach.

## 1. Keeping two spells

**Not drag-and-drop.** Dragging a spell into a custom SIDL slot needs client internals we do not have mapped, and §16 records how that class of assumption has cost us. Instead: the spell window's **Known** tab already lists everything scribed — select one, press **Keep**. Two slots, shown on the same tab.

**The cost — forfeited picks.** `spell_choice` records the level at which each spell was awarded:

```
spellpick_lvl_<charid> = "<spell_id>:<level>,..."
```

On death the two kept spells' *origin levels* are carried into the next run as spent:

```
picks_spent_<charid> = "32,35"
```

and `spell_choice.offer` returns early at those levels.

- ⚠️ Record the level **at award time**, not on death. Working it out later means guessing from the spell's own `classes8`, which is the level it *becomes available*, not the level you happened to be offered it.
- ⚠️ The forfeit must be **checked against the level band, not the exact level** if `LEVEL_BAND` offers a spell above your level — otherwise a spell picked at 32 that is nominally level 30 forfeits the wrong pick.
- 📌 The trade is genuinely neutral in *count* (2 kept, 2 picks lost) and positive in *control* — you swap two random offers for two known-good spells. That is the point, and it is why it does not dictate a run.

## 2. Parchment Fragments

- New item, **not Lore, tradeable, stackable**, id from the free band (suggest **147920**).
- Awarded in `death_loss.process`, **one per spell actually destroyed** — count the spellbook before `UnscribeSpellAll`. A full run to cap scribes ~**31** spells, so a deep death yields ~31 fragments and a shallow one yields almost none. Income already scales with how far you got, with no extra tuning.
- ⚠️ Award **after** the wipe but count **before** it, same ordering trap as the class auras.
- ⚠️ Tradeable means an economy: fragments become the currency of the upgrade system. That is presumably intended, but it also means a player can buy ranks with plat via other players. Flagging, not objecting.

## 3. The global drop — "Ink of the Lost" (suggest **147921**)

A single `global_loot` row. Suggested shape:

| field | value | why |
|---|---|---|
| `enabled` | 1 | |
| `min_level` | 10 | stops level-1 farming being the optimal source |
| `rare` | 0 | every mob, not just named |
| `raid` | 0 | |

⚠️ `global_loot` has **no chance column** — the rate lives in the `loottable`/`lootdrop` rows it points at, so the drop chance is set there. Build it as its own loottable with a single low-chance entry.

## 4. The upgrade recipe

⚠️ **A spell is not an item, so it cannot go in the crucible.** The combine produces a *token*; the token is then spent on a kept spell from the spell window.

```
  N x Parchment Fragment  +  M x Ink of the Lost     --[Refining Crucible]-->  1 x Rank Sigil
  Rank Sigil  +  select a kept spell in the window   -->  that spell goes rank N -> N+1
```

Suggested curve, against ~31 fragments per deep death:

| rank | fragments | ink | ≈ deaths | ≈ inks |
|---:|---:|---:|---:|---:|
| 1 | 30 | 1 | 1 | 1 |
| 2 | 60 | 2 | 2 | 2 |
| 3 | 120 | 4 | 4 | 4 |
| 4 | 240 | 8 | 8 | 8 |
| 5 | 480 | 16 | ~15 | 16 |

Total to rank 5: **930 fragments + 31 ink** ≈ 30 deep runs. Rank 1 costs a single good run ("difficult, but not impossible"); rank 5 is a long project ("quite difficult"). Doubling per rank is the same shape the delve's tier costs use.

- 📌 Numbers are a first guess and should move once fragment income is observed rather than modelled.
- ⚠️ Cap the rank at 5 **server-side**. The window sends a request; the server decides.

## Build order

1. **Fragments + global drop** — pure SQL/Lua, no rebuild, immediately testable, and generates the currency before anything spends it.
2. **Keep-2 + forfeited picks** — Lua + generated XML. Self-contained and playable on its own; the kept spell is worth having even at rank 0.
3. **Ranks** — the C++ hooks and the token. Last, because it is the only part that needs a zone rebuild and the only part with unresolved risk.

## Open questions

1. **Does the client block a cast on its own mana figure?** Decides whether −5%/rank is real or cosmetic. *Answer before building step 3.*
2. **Ranks on buffs — in or out of v1?** Recommend out.
3. **Should a kept spell arrive already scribed at level 1**, or wait until you reach its level? Arriving at 1 hands a fresh character a level-32 heal.
4. **What happens to rank if you stop keeping a spell?** Suggest the rank persists against the spell id, so re-keeping restores it — otherwise unkeeping silently destroys a 30-run investment.
