## ⚠️⚠️ 0. THE REBUILD IS THE FIRST THING — read this before anything else

**A container rebuild is PENDING and is the reason this doc exists.** Two files were edited together
and **must stay together**:

| file | change |
|---|---|
| `.devcontainer/override/eqemu_config.json` | `server.zones.ports` **7000-7005 → 7000-7029** |
| `.devcontainer/devcontainer.json` | `appPort` **`7000-7029:7000-7029/udp`** (was six single lines) |

**Why:** six zone ports was one per running zone, and every booted zone holds its port for its
lifetime. With the tutorial plus a few dynamic zones already up, asking world for one more zone hit
*"World did not have a port to assign from this server, the port range was not large enough"* — the
client's version of which is **"That zone is unavailable"** and a bounce to character select. That is
exactly what happened pressing **Enter** on the Delve window. Instanced content makes it routine:
**every delve run is another zone.**

### ⚠️ WORLD WAS DELIBERATELY NOT RESTARTED
The config change is on disk but **not live**. That is intentional:

> Widening only the server config boots zones on ports the Windows client **cannot reach**, turning a
> clear error into a **silent timeout on zone-in**. Strictly worse to debug. Both halves, or neither.

So: **rebuild the container, then start the stack.** Do not restart world before the rebuild.

### After the rebuild
1. The DB **survives** (named volume `aotv4-mysql-data`). If `peq` is somehow missing,
   **STOP and read `POST_REBUILD_RECOVERY.md` §STEP 0** — the previous container may still hold it,
   and importing a snapshot would silently discard work.
2. Start the stack (`POST_REBUILD_RECOVERY.md` step 6). Order: loginserver, world, `eqlaunch zone`,
   ucs, queryserv. Exactly **one** eqlaunch.
3. Sanity check the fix:
   ```bash
   grep -A3 '"ports"' /src/build/bin/eqemu_config.json     # expect 7000 / 7029
   ss -lunp | grep -c ':70'                                # zones now free to boot past 6
   ```
4. `/delve` → pick level 1 → **Enter**. It should no longer bounce.

## 2. What was built this session

### §22 — Combat specials cost endurance
`AoT:SpecialEndurancePct` (50) / `SpecialEnduranceMinToUse` (1), charged in
`Mob::DoSpecialAttackDamage` — the one choke point every special funnels through. Charged **after**
the hit because the cost is a share of the damage. ⚠️ The reuse timer still starts on a winded whiff,
deliberately. **Compiled and live.**

### The Sinew line — a damage tap returning endurance (§5)
Ids **43318-43323**, 75% damage / 25% endurance (return = damage ÷ 3). The counterpart to §22.
**Live**, spells in shared memory, client files exported and staged.

⚠️ **`spells_us.txt` + `dbstr_us.txt` must be reinstalled** from
`C:\AoTv3\AoTv4\aotv4_client_install` or the client shows the old scaling damage. **Do this after
the rebuild if you have not already.**

### The engine bug this uncovered — Lua spell scripts on NPC targets (§10)
`SpellArgumentDispatch` never registered `EVENT_SPELL_EFFECT_NPC`, so it fell through to
`handle_spell_null` — an **empty function** — and the Lua event table arrived with **no fields at
all**. The script still ran; every field was just nil.

**This meant the Moonfire line's bonus heal had never worked in play** — 22 of 56 spell scripts were
dead against monsters. Fixed in `zone/lua_parser.cpp` (registration only; `handle_spell_event` was
already written for it). **Compiled and live.**

### §23 — `quest_difficulty.pl`
Scores 2,743 quests as `<level band>.<at-level difficulty>`. Read-only. Three modelling bugs found
and fixed along the way (see §24 of CLAUDE.md and the script header).

### Gear tiers — a tier now REPLACES the drop (§10)
`AddTierUpgrades` → `NPC::ResolveTierDrop`. It used to roll both tiers **independently and add them
on top of the base**, so one item could put three on a corpse. Now one item in, one out: 5% Mythic /
25% Hallowed / 70% native. **Compiled and live.** ⚠️ Expect slightly fewer Hallowed and meaningfully
fewer items per kill.

### §24 — The Delve system (the bulk of the session)
Pick a level → private **dynamic zone** of a DoN mission → quest in the journal → kill → chest →
next rung unlocks. **Pure Lua + SQL + one window; no C++ server change.**

- **15 rungs, level 1 → 70** in fives, cycling 6 DoN zones at their **mission versions** (never
  version 0 — that is the open-world spawn set).
- **Player-relative scaling** (`aotv4_dungeon_scale.lua`): the rung level is the floor; how far above
  the naked expectation your gear puts you moves it. `/say delvepower` explains itself axis by axis.
- **Score sheet**: quadratic per-kill value, banked **at the moment each mob dies**, so gear-swapping
  at the end cannot inflate it. Run history with a level-band breakdown, Death Book style.
- **Real DZ** as of the last change: `CreateExpedition` + `MovePCDynamicZone`, with compass, safe
  return, and replay lockout **disabled** (a repeatable ladder must not be gated by a cooldown).

## 5. Open questions

- **Score is raw and uncapped.** A long grind in a soft rung can out-total a short hard clear. If
  difficulty should dominate volume, `avg × kills^0.7` is the shape — but that wants real numbers
  first.
- **Scale reference is the first client in the instance.** Fine solo; for groups it should be the
  strongest member or an average.
- **Chest is empty.** `AddLooter` is on `Lua_Corpse`, not `Lua_NPC`, so loot rights need setting on
  the corpse after it opens. Loot was explicitly out of scope.
- **Group entry** is not built — `CreateExpedition` takes min/max players (1/6) but only the creator
  is added.
- **Rewards** are not wired to the score sheet at all yet. The ledger exists and is honest; nothing
  consumes it.
- **Torghast-style in-run powers** (the original ask) are not started. The reward picker's typed
  tokens (`S:` / `K:`) were identified as the natural seam — add an `A:` type.

## 6. Traps this session added to CLAUDE.md

Worth skimming before touching any of it again:

- **`eq.get_zone_id()` takes NO arguments** — it returns the *current* zone. Silently broke Exit.
- **`e.other` is a `Lua_Mob`, not a `Lua_Client`** — `IsClient()` is true but `CharacterID` is nil.
  Resolve via `GetClientByID(mob:GetID())`. Crashed on **every kill**.
- **Instance version 0 is the open world** — instancing it gives a private copy of the ordinary zone.
- **`ScaleNPC` before `ModifyNPCStat`**, always — it rewrites stats wholesale.
- **Cloning a stock spell inherits `formulaN`/`maxN`** — overriding the base damage is not enough.
  Sinewbite dealt 67 instead of 27 for this reason.
- **A re-runnable SQL script's cleanup `DELETE` must only name ids it created** — moonfire's swept up
  the entire Sinew line.
- **Rescaling mobs mid-run is out-of-combat only** — otherwise you refill a mob you are fighting.
